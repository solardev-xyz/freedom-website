Developers

Build for the browser that runs the network

Freedom runs Swarm, IPFS and Radicle nodes on the user's own machine. These documents describe what a page can do with them. They live in the Freedom repository and are linked here at version {{version}}.

Page APIs

Swarm Provider API (window.swarm)

Lets a web page publish to Swarm, read and write chunks and feeds, sign with a publisher identity, and send and receive PSS/GSOC messages, all through the user's own Swarm node, with per-origin consent. Spec version 1.0.

Radicle Provider API (window.radicle)

Lets web applications act on the user's local Radicle node: seed repositories, sync, disclose the user's Radicle identity, and write collaborative objects such as issues and comments, with user consent and origin-scoped permissions. Reads are plain rad: URL fetches. Draft v0.1.

WebMCP in Freedom Agent

Freedom Agent can discover and invoke tools registered by the currently loaded page, both JavaScript registrations and native declarative forms. Sites without WebMCP tools still work through ordinary browser actions.

Publishing sites

Swarm sites (bzz://)

How Freedom loads bzz:// pages, including ENS-named hosts such as bzz://swarm.eth, the origin model, and what to check when moving a site from gateway URLs to the bzz:// scheme.

IPFS sites (ipfs://, ipns://)

How ipfs:// and ipns:// URLs and ENS names resolve, and why sub-resources should be published with CIDv1 base32 addresses.

Contract-hosted apps (web3://)

Native support for the draft ERC-8244 html() interface: an application whose whole document lives in contract storage, opened as web3://<contract>:<chainId>/ with no HTTP gateway in the path.

Work on Freedom itself

Freedom is open source under the MPL-2.0. The development guide covers local setup, tests and builds, and CONTRIBUTING.md explains how to propose a change. Bugs and ideas go to GitHub issues, and you can talk to the team on Telegram.
